# 不会写代码的我，用 AI 把技能发布到了 GitHub——C4→C5 实战

> 一个开学前连 GitHub 是什么都不知道的大一新生，是怎么靠 AI，把自己做的四个"小技能"堂堂正正发到一个开源仓库里的？这篇讲全过程，包括我对着"连接超时"发呆的那个下午。

## 先说清楚，我有多"菜"

我是李亚轩，郑州西亚斯学院软件工程 2025 级。

如果我说我是零基础，你可能觉得我在谦虚。真不是。开学那会，我对"代码"的全部认知，停留在课上跟着老师敲的几行 C 语言。

而 GitHub 呢？我第一次听到这个词的时候，内心 OS 是：这是个啥网站？能吃吗？

就是这么一个我，现在有一个自己的开源仓库，里面躺着我做的四个"技能"，全世界任何人都能看到、能下载。

这中间发生了什么？这篇文章就把它讲明白。

## 第一步：我先做了四个"技能"（C4）

故事得从 C4 这个挑战说起。它要求我把自己会做的一件事，沉淀成一个**别人拿过去就能用的"技能包"**。

我做了哪四个？说出来你可能觉得很朴素：

- 一个帮我把普通 Markdown 文章，排成能直接粘进公众号的样子的技能；
- 一个帮我把作业题目自动求解、顺便排好版的技能；
- 一个在本地大模型上跑 Agent 的技能（就是我上篇写的那个）；
- 一个自动评审技能、挑毛病的技能。

你看，没有一个是什么惊天动地的黑科技。但它们有个共同点：**都是我自己真的遇到过的麻烦，然后我把解决办法打包了。**

做这四个技能的过程，基本上就是我把需求讲给 AI 听，它帮我搭骨架，我来填肉、改细节、反复试。做着做着我发现——

**"会做一个东西"和"把它做成别人也能用的东西"，中间隔着一整个太平洋。**

你自己用，能跑就行；别人用，你得写清楚怎么装、怎么用、出错了咋办。这个"说明文档"差点把我逼疯。

## 第二步：东西做出来了，然后呢？藏自己电脑里？

四个技能躺在我电脑桌面上，像四个没人看的作品。

C5 这个挑战就是来解决这个的：**把它开源，发布到 GitHub，让它真正变成一个"项目"。**

我当时的心情很矛盾：一方面觉得"哇我要开源了好酷"，一方面又怕——听说 GitHub 都是大神用的，我这种连命令行都不利索的，不会上去就被劝退吧？

事实证明，劝退是真的。但不是被大神，是被一个我完全没预料到的东西。

## 那个让我卡了一下午的"连接超时"

按照教程，发布代码一般是用一个叫 `git` 的工具，敲几条命令，把本地文件"推"上去。

我照做了。然后命令行给我返回了一个特别冷酷的报错：**连接超时。**

我以为是网不好，重连。还超时。
我以为是命令敲错了，让 AI 帮我看。它说命令没问题。
我重启了电脑。还超时。

我就对着这个报错，发了整整一下午的呆。那种感觉特别憋屈：**东西明明做好了，就是送不上去。**

后来我跟 AI 把完整报错、我的网络环境、机器系统全描述了一遍，它帮我定位到一个我根本想不到的原因：**不是我代码的问题，是我这台机器从 git 这个工具直连 GitHub 服务器，网络就是不通。**

这时候正常人可能就放弃了。但 AI 给了我一条完全不同的路：

> 既然 git 这个工具连不上，那我们干脆不用它。GitHub 本身有一套"网页接口"，我们用 Python 直接通过这个接口把文件传上去。

就这么一句话，把我从死胡同里拽了出来。

**我没用 git push，我是用一段 Python 脚本，通过 GitHub 的开放接口，一个文件一个文件"递"上去的。** 最后仓库一个文件没少，整整齐齐。

## 整个过程，我到底在干嘛？

事后我复盘，我其实做了这几件特别朴素的事：

1. **注册了账号，建了个空仓库。** 这一步 AI 全程带着我，点哪里、填什么名字。
2. **给文件分了类。** 不能一股脑全堆根目录。文章放 `articles/`，说明放根目录，追踪表放 `tracking/`。文件夹结构本身，就是给看的人写的第一份说明。
3. **一个文件一个文件地传。** 用那个绕开超时的脚本，传完一个，我就去网页上点开看一眼——**真的在。** 那种确认的快乐，比想象中大。
4. **写 README。** 这是仓库的门面。别人点进来，三秒钟看不懂这是啥，就走了。

最让我有成就感的，是第 3 步的那个"真的在"。

**我做的东西，第一次不是存在我自己电脑里，而是挂在一个全世界都能访问的地方。** 这种"它真的存在了"的实感，是我以前在宿舍里自己瞎鼓捣从来没有过的。

## 几句大实话

走完 C4 到 C5 这一圈，我想说几句掏心窝的：

- **"不会写代码"根本不是借口。** 我写不出多漂亮的代码，但我会把问题讲清楚，会让 AI 帮我查错，会死磕到它跑通。这就够开始了。
- **卡住的时候，换条路比死磕重要。** 那个超时卡死我一下午，最后解法是"绕开 git"。别在一条堵死的路上反复踩油门。
- **说明文档不是可有可无的。** 你的东西再牛，别人看不懂等于零。写清楚"这是啥、怎么用"，本身就是一种能力。
- **公开这件事，会反过来逼你认真。** 一旦知道全世界都能看到，我写文档、整理文件夹的时候，都会不自觉地认真起来。

一个月前我连 GitHub 是啥都不知道。现在，我有一个开源仓库，里面是我自己做的四个技能。

**我没有变成大神。但我从一个"只会在自己电脑里瞎玩的人"，变成了一个"能把东西正经发出去给人看的人"。** 这一步，比技术本身值钱多了。
